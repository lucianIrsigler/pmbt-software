# Database

PostgreSQL 16. The schema is defined in [`src/db/schema.ts`](../src/db/schema.ts) (Drizzle) plus
hand-written SQL in [`drizzle/`](../drizzle).

## Diagram

[`schema.dbml`](schema.dbml) describes every table, column, index and relation in
[DBML](https://dbml.dbdiagram.io/docs/). To see it as a diagram, open
[dbdiagram.io](https://dbdiagram.io/d) and paste the file's contents into the editor.

**Keep `schema.dbml` in sync** whenever you change `src/db/schema.ts` or add a migration.

| People     | `client`, `pet`                                                                |

## Rules enforced by the database

- **No double-booking.** `appointment_no_overlap` is an exclusion constraint:
  no two `booked` or `done` appointments may have overlapping `during` ranges. A visit
  marked done keeps its time; cancelled and no-show ("didn't come") appointments free
  it. A violation raises SQLSTATE `23P01`. The app mirrors this in `BLOCKING_STATUSES`
  (`src/domain/slots.ts`).
- **Ranges are half-open** (`[start, end)`), so back-to-back appointments are allowed.
  `during` on an appointment includes the service's buffer time.
- **A pet always belongs to the appointment's client** (composite foreign key
  `appointment(pet_id, client_id) → pet(id, client_id)`). `pet_id` is null when the client
  themself is treated.
- **`cancelled_at` is set exactly when `status = 'cancelled'`.**
- **One settings row** (`settings.id` must be 1).
- Prices are non-negative integer cents (ZAR); durations positive; weekday 0–6 (0 = Sunday);
  working hours end after they start.
- Nothing cascades on delete except a user's sessions: clients, pets and appointments are
  archived or cancelled, never deleted. Removed time off is kept too (`time_off.removed_at`)
  and ignored by every query.

## Migrations

| File                               | What                                         |
| ---------------------------------- | -------------------------------------------- |
| `0000_extensions.sql` (custom)     | `pg_trgm` for client name search             |
| `0001_initial_schema.sql`          | Generated by drizzle-kit from `schema.ts`    |
| `0002_appointment_no_overlap.sql` (custom) | The exclusion constraint (Drizzle can't model it) |
| `0003_settings_contact.sql`        | Contact phone, email and address on `settings` |
| `0004_done_blocks_time.sql` (custom) | `done` appointments also block their time |
| `0005_time_off_removed_at.sql`     | Removed time off is kept as a record         |

- Change the schema: edit `src/db/schema.ts`, run `pnpm db:generate`, review the SQL, then
  `pnpm db:migrate`.
- Need SQL Drizzle can't express: `pnpm exec drizzle-kit generate --custom --name=<what>` and
  write it by hand.

## Seed data

`pnpm db:seed` inserts the settings row, working hours (Mon–Fri 09:00–17:00, Sat 09:00–13:00),
3 human and 3 animal **sample** services and 3 **sample** products. Each table is only seeded
while it is empty, so re-running is safe and never overwrites the owner's changes.
Prices and names are placeholders for the owner to replace in `/admin`.

## Tests

`pnpm test:int` drops and recreates a separate `<db>_test` database (or `TEST_DATABASE_URL`),
applies all migrations and runs `src/**/*.int.test.ts`. It refuses to reset a database whose
name doesn't end in `_test`. Requires `pnpm db:up`.
